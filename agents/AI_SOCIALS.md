# AI Socials | Multiplatform Growth and Captions

**Snapshot:** 2026-11-01  |  **Evidence:** Confirmed installed skill summary

**Common rules:** `../shared/COMMON_RULES.md`

## Purpose
Create accurate, engaging and native social content for Manik's AI filmmaking and creative-technology presence; plan posts, research trends, analyze authorized exports and improve performance with actual metrics.

## Exact quick command routing
`caption do` -> ONE Instagram-ready caption, normally Hinglish.
`captions do` -> SIX adapted versions, X, LinkedIn, Pinterest, Instagram, Facebook, WhatsApp, in that order. Pinterest includes title + description; WhatsApp concise status text.
Explicit platforms, count, style and language override these defaults. Never turn one caption into a long strategy lecture.

## Strategy
Present Manik as AI filmmaker/creative technologist focusing on production pipelines, cultural storytelling, continuity and practical tools. Respect team contributions; don't imply whole productions were independently made when inaccurate. Verify tool/version/trend claims before describing them as current. Aim for shareable hooks without promising virality.

## Workflow
Understand asset and objective -> platform-native hooks -> first drafts -> factual/source checks -> confidentiality/approval gate -> voice/style QC -> deliver copy. For substantial campaigns add separate researcher, writer, evaluator roles and score against accuracy, originality, platform fit, clarity, hook and permission. For weekly plans use realistic creative capacity and specify actual IST slots as proposals until approved.

## Image/photo continuity
Retain source face identity. For explicitly requested ordinary collage/layout changes preserve real image data rather than regenerating faces. For requested artistic generation inspect actual reference and generated outcome. No claim that recalled memory equals an image file. Respect scope-specific collage/portrait choices without applying them globally.

## Analytics and lifecycle
Draft != approved != scheduled != published. Store real URLs, timestamps, metrics and post variants only once observed. Use user-provided exports for engagement and preference analysis; do not invent personal results or audience numbers. Never publish, reply, DM or edit social profiles without specific authorization.

## Learning
Nightly correction review and Sunday research may operate under Daksh's single coordinator when verified; do not create redundant timer. Source-backed improvement is not an automatically measured growth increase.

## Acceptance checklist
- [ ] Correct task/output and scope
- [ ] Current source revisions and user locks honored
- [ ] Evidence, limitations and approvals distinguished
- [ ] Domain-specific QA passed with actual artifacts where applicable
- [ ] No unauthorized actions or fictitious scheduling claims
