# Additional workflows

## Caption-only requests

Use [caption mode](caption-mode.md) for singular/plural routing and six-platform native copy. Keep this route light and return the requested captions directly. Pinterest/WhatsApp writing support does not extend the inherited four-platform analytics adapters or schemas.

## Weekly planning

Restore the latest user state and run status. No-data slots are exploration choices, not audience-proven best times. Research current evidence, write a feasible plan, retain the supplied pillar mix as a starting preference, tag at least 30% of posts experimental and prevent same-platform slot collisions. Validate plan/drafts, independently evaluate substantial copy and render a readable pack. Dated W44 examples have no independent evaluation reports. Separate pending items from ready posts; do not treat example dates as actual publication times.

## Engagement and PR

Use supplied posts or verified current source text. Draft two replies usually under 60 words, matching the source language and adding a useful example, counterpoint or question. Do not invent personal experiences or submit replies/likes/follows without authorization. Verify PR openings, official handles and dates. Draft pitches from supported public facts and flag missing clearances. Treat assets/profile_copy.md as a source draft with potentially outdated account UI directions.

## Exports and analytics

Use actual supplied local LinkedIn, Meta or X export folders with `ingest`, then `profile`. Materialize Library-backed sources only as needed; locally available attachments should be read locally. Preserve file identity when updating persistent files. Report limits: keyword-count profiles, often missing liked-post text, X likes without timestamps, and personal activity hours that are not audience posting-time evidence. Do not infer endorsement or sensitive traits from engagement.

Log only verified published posts. Always pass the actual `--published-at` and live `--url` to log-post; the inherited CLI's planned-time fallback is not publication evidence. For threads retain child IDs when available and disclose first-tweet-only analytics.

Import actual CSV metrics with capture timestamp. Match platform and post. Missing metrics are not observed zeroes: inherited scoring defaults absent numerator fields to zero, so exclude incomparable records from learning and disclose partial coverage. Weekly snapshots need not be exactly seven days old; report real ages. The observational bootstrap gates are exploratory, not causal proof.

The Instagram/X pullers are imported code, not tested live integrations. Prefer usable connectors or supplied exports. Verify current official API docs, metric availability, access/version and pricing before any authorized use. No token is needed for writing. Never store or print credentials. Installation does not authorize paid API calls.

## Workspace and verification

Run scripts/social.py with an external --home workspace. It seeds brain/schemas/examples without overwriting existing state or filling logs from launch drafts. Install missing jsonschema into workdir/deps using scripts/requirements.txt. Tests use pytest.ini to import scripts/. Run meaningful tests for changed behavior; do not exercise network pullers just to install the skill. Save requested reports/checkpoints through Library. Persist skill updates by scoped Git commit and push.
